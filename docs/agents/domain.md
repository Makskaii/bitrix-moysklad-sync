# Domain docs

This project uses a single domain context. Before exploring or changing an area, read `CONTEXT.md` at the project root if it exists and relevant ADRs in `docs/adr/` if they exist. Proceed when those files are absent; create them only when domain terminology or a consequential decision needs recording.

Use the glossary's terms in specifications, issues, tests, and code. Surface a conflict with an existing ADR instead of silently overriding it.
